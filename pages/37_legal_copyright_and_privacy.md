# Legal: Copyright and Privacy

::content::

Software developers must follow laws that protect **intellectual property** and **personal information**.

Three key pieces of legislation apply:

- **Copyright Act 1968** (Commonwealth)
- **Privacy Act 1988** (Commonwealth)
- **Privacy and Data Protection Act 2014** (Victoria)

# What is Copyright?

::content::

**Copyright** protects original creative work.

It applies **automatically**. There is no need to register it.

For software, this covers:

- Source code
- Documentation
- User interface designs
- Graphics and images

# Who Owns the Copyright?

::content::

The **creator** usually owns the copyright to their work.

If you write code as an **employee**, your employer usually owns it instead.

Freelancers and contractors may keep ownership - this depends on their **contract**.

Copyright can be **sold or licensed** to others.

# Copyright and Software Development

::content::

Copying someone else's code without permission can **breach copyright**.

Open-source libraries come with a **licence** (e.g. MIT, GPL).

Every licence has different rules. Always check what it allows before using the code.

# Copyright in Practice

::left::

### Copyright protects developers by

- Stopping others reselling their work
- Letting them licence their software for money
- Giving them legal options if their work is stolen

::right::

### Developers must

- Check licences before using code
- Give credit where a licence requires it
- Avoid copying code without permission

# Privacy Legislation

::content::

Privacy laws protect **personal information**.

Personal information is anything that can identify a person, e.g. name, address, or date of birth.

Two laws apply in Victoria:

- **Privacy Act 1988** (Commonwealth)
- **Privacy and Data Protection Act 2014** (Victoria)

::title::

# Privacy Act 1988

::content::

This is a **Commonwealth** law.

It applies to most **private organisations** and **federal government agencies**.

It sets out **13 Australian Privacy Principles (APPs)** that these organisations must follow.

---

::title::

# Relevant APPs

::content::

This unit focuses on five of the 13 APPs:

- **APP 1** - Open and transparent management: have a clear, available privacy policy
- **APP 6** - Use or disclosure: only use data for the purpose it was collected for
- **APP 8** - Cross-border disclosure: take care sending data overseas
- **APP 9** - Government related identifiers: don't adopt IDs like Medicare numbers as your own
- **APP 11** - Security: protect personal information from loss or misuse

> If in doubt - whenever a question arises about privacy - you almost always want to mention "Privacy Policy". APPs 1, 6 and 8 are all covered by a comprehensive privacy policy.

# Privacy and Data Protection Act 2014

::content::

This is a **Victorian** law.

It applies to the **Victorian public sector** - e.g. government departments, schools, and local councils.

It sets out similar rules: the **Information Privacy Principles (IPPs)**.

::title::

# Relevant IPPs

::content::

This unit focuses on five of the 10 IPPs:

- **IPP 1** - Collection: only collect personal information that is necessary, and collect it fairly
- **IPP 2** - Use and disclosure: only use data for the purpose it was collected for
- **IPP 4** - Data security: protect personal information from loss or unauthorised access
- **IPP 5** - Openness: have clear policies on how personal information is managed
- **IPP 9** - Transborder data flows: take care when personal information leaves Victoria

> **From Unit 3 (not assessable here):** you also met **IPP 7** - Unique identifiers: don't assign your own ID to someone who already has one from another organisation. And **IPP 10** - Sensitive information: extra care is needed for data like health, race, or religion, which usually needs consent to collect.

# Privacy and Software Development

::content::

Software that collects personal information must follow these principles.

- Only use data for the purpose it was collected for
- Store data securely
- Let people view and correct their own information

::title::

# Privacy in Practice

::left::

### Developers should design systems that

- Collect only the data that is needed
- Encrypt sensitive data
- Let users view, update, or delete their data

::right::

### Common privacy risks

- Collecting more data than necessary
- Weak storage security
- Sharing data without consent
